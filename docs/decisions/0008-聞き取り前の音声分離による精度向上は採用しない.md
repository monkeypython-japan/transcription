# 0008. 聞き取り前の音声分離（Demucs）による精度向上は採用しない

## 状況

統括プロジェクトより TRI-2 として、聞き取り前に Demucs 等で音声分離を行い
BGM・効果音を除去してからセリフ成分のみを ASR に渡すことで精度が上がるか
検証してほしいとの申し送りがあった。着想の経緯・仮説は Vault の discussion
ノート（`discussion/2026-08-10-聞き取り前の音声分離によるセリフ欠落ハルシネーション対策の検討.md`）を参照。

[[0006-parakeetのセリフ欠落対策としてbeam探索とoverlap拡大を導入|ADR 0006]] で判明した
Parakeet の欠落原因のうち「Greedy 探索自体が節を丸ごと読み飛ばす」問題（TDT/RNNT系
モデルが低S/N比のフレームで blank に倒れやすい性質に起因すると推測）に対し、事前に
音声分離でセリフのS/N比を上げれば、より軽い Greedy 探索でも [[0007-既定のasrエンジンをwhisperに戻す|ADR 0007]]
時点の Beam(5) 相当の精度に迫れるのではという仮説を検証した。

## 調査

[[0006-parakeetのセリフ欠落対策としてbeam探索とoverlap拡大を導入|ADR 0006]] と同じ手法・同じ
ファイル（`/Users/mamoru/Temp/The_Questor_Tapes.mp4`、英語音声、約90分）を用いた。

1. Demucs（`htdemucs` モデル、`--two-stems=vocals`、Apple Silicon GPU(mps)使用）で
   全編を分離し、vocals（セリフ成分と推定される音声）を抽出
2. 分離前後・Greedy/Beam(5) の組み合わせで4条件を全編書き起こし、Whisper（同ファイルを
   別途書き起こした基準）との突き合わせを `difflib.SequenceMatcher` で実施し、
   Whisper 側にのみ存在する4語以上の連続語句（欠落候補）、および Parakeet 側にのみ
   存在する4語以上の連続語句（挿入候補＝疑似ハルシネーション・分離アーティファクト疑い）を集計

### 結果

| 条件 | 欠落候補(4語+) | うち大欠落(20語+) | 挿入候補(4語+) | 処理時間 |
|---|---:|---:|---:|---:|
| Greedy／分離なし（[[0006-parakeetのセリフ欠落対策としてbeam探索とoverlap拡大を導入\|ADR 0006]]以前の既定相当） | 46件 | 14件 | 9件 | 367秒 |
| **Beam(5)／分離なし（現行既定）** | **36件** | **4件** | 11件 | 1185秒 |
| Greedy／分離あり | 45件 | 11件 | 8件 | 456秒（分離前処理1534秒を含めると約1990秒） |
| Beam(5)／分離あり | 36件 | 11件 | 12件 | 1151秒（分離前処理込みで約2685秒） |

（Demucs分離自体の処理時間: 1534秒。参考として本検証の基準に使った Whisper の処理時間: 902秒）

## 結論

**採用しない。** 以下の3点から、音声分離を前処理に加える効果は確認できなかった。

1. **「Greedy＋分離」は「Beam＋分離なし（現行既定）」に精度で迫れない**: 欠落候補
   45件 対 36件、大欠落11件 対 4件で、現行既定の方が明確に良い。処理時間面でも、
   分離の前処理コスト（1534秒）を含めると Greedy＋分離の総処理時間（約1990秒）は
   Beam単体（1185秒）より長く、「より軽い処理時間で迫る」という当初の仮説も成立しなかった
2. **Beam に分離を組み合わせても改善しない**: 欠落候補の総数はBeam単体と同じ36件だが、
   大欠落（1〜2文まるごとの欠落）が4件→11件に増加した。総数が変わらないまま大欠落が
   増えているのは、分離により隣接する小さな欠落が結合し、より大きな塊として欠落する
   方向に働いた可能性を示唆する。分離を追加する明確なメリットが無いばかりか、
   大欠落という実害の大きい欠落が悪化する望ましくない傾向が見られた
3. **分離アーティファクトによる誤認識の疑い**: 挿入候補の件数自体は分離あり／なしで
   大差ないが（8〜12件で同水準）、分離あり特有の挿入内容（例:
   `quester that message you left curious world jerry squalor ugliness greed struggle yep so much beauty`
   のような15語の挿入が Greedy・Beam 双方の分離ありで共通して出現）には、別区間の
   セリフや音源分離由来のノイズが混入したと見られるものがあり、[[../../CLAUDE.md]]
   の discussion ノートで事前に懸念されていた「分離アーティファクトが未知の分布の
   ノイズとなり、かえって精度を落とす可能性」を裏付ける結果となった

discussion ノートで検討したもう一つの観点（映画のセリフに対する UVR/MDX-Net 等の
分離品質、Whisper 側のハルシネーションへの効果）は、Demucs 単体の結果が明確に
非採用と判断できたため追加検証しなかった。

## 却下案

- **UVR (Ultimate Vocal Remover) / MDX-Net 等、他の分離ツールで再検証する**: discussion
  ノートで候補に挙がっていたが、今回の Demucs での結果が「総数据え置き・大欠落悪化・
  処理時間増」と明確に非採用の方向だったため、ツールを変えての再検証は見送る。
  分離ツールが変わっても「セリフ以外の音（BGM・効果音・別区間のセリフ）を誤って
  ボーカルとして残す／セリフを誤って除去する」というアーティファクトの発生様式自体は
  同種の課題として残ると考えられる
- **Whisper 経路（現行既定）に分離を組み合わせて検証する**: discussion ノートで
  「Whisper のハルシネーションへの効果も不透明」と指摘されていた観点。今回
  Parakeet 側で明確に非採用と判断できたため、Whisper 側の追加検証は行わなかった。
  将来 Whisper 側のハルシネーション対策を別途検討する際の材料として、必要になれば
  改めて着手する

## 影響

- コード変更なし。既定構成（[[0007-既定のasrエンジンをwhisperに戻す|ADR 0007]] の
  Whisper 既定、`asr_engine = "parakeet"` 明示時は
  [[0006-parakeetのセリフ欠落対策としてbeam探索とoverlap拡大を導入|ADR 0006]] の
  Beam(5)＋overlap 30秒）を維持する
- 検証のため Demucs を作業用の venv に一時的にインストールしたが、`requirements.txt`
  には追加していない（不採用のため本番依存には加えない）
