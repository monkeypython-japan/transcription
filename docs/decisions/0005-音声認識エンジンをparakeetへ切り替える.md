# 0005. 音声認識エンジンを Parakeet 対応のハイブリッド構成にする

## 状況

mlx-whisper（whisper-large-v3-mlx）は無音区間でのハルシネーション（存在しない発話の生成）が根本的な課題として残っていた。`no_speech_threshold` 等のチューニング（[[0001-mlx-whisper-への移行|0001]]）で軽減はしたが、解消はしていない。

NVIDIA の Parakeet（parakeet-mlx 実装、`mlx-community/parakeet-tdt-0.6b-v3`）を実機検証した結果、以下が確認された。

- **ハルシネーション**: 台詞ゼロ区間12分（2001年宇宙の旅、市販英語字幕を正解データとして使用）で、Parakeet はセグメント0件、Whisper は16件を捏造（`Thank you.`×7, `I'm sorry.`×3, `¶¶`×4, `김`×1, `© transcript Emily Beynon`×1）
- **精度**: 台詞区間の WER は Whisper がわずかに優位（Parakeet 31.9%/14.0% vs Whisper 27.8%/13.3%、2クリップで計測）
- **速度**: Parakeet が約6倍高速（3分クリップで 4.9〜5.6秒 vs 31.6〜33.2秒）
- **対応言語**: Parakeet は英語含む欧州25言語のみ対応。日本語・中国語・韓国語は非対応
- **言語自動検出**: Parakeet には無い（Whisper にはある）
- **既知の Issue**: parakeet-mlx 0.5.2 / mlx 0.32.0 で Issue #49（`mx.concat(axis=)`）は再現しない
- **実測されたバグ**: 文末の句読点のみのトークンが、直前の実トークンから大きく遅れて出力されることがある。`AlignedSentence.end` が `tokens[-1].end` から算出される仕様のため、そのままではセグメント終端が不当に引き伸ばされる。実例（本プロジェクトでの実機検証時）:
  ```
  ' time'  end=130.28   ← 発話はここで終了
  '.'      start=147.88 dur=0.32 end=148.20  ← セグメント終端が148.20 になる（19.8秒のブロック）
  ```
- **セグメントが長すぎる問題**: Parakeet は息継ぎのない長い一文を、そのまま1セグメントとして出力する。上記の句読点バグとは別問題で、`2001: A Space Odyssey` のナレーション区間で **24.08秒**のセグメントが実測された（トークンは 52.64〜76.72 まで連続、2秒超のギャップ無し、末尾句読点の遅延も無し）。同区間の Whisper は最長 4.4 秒に割れており、字幕として1枚が24秒間表示され続けるのは実用に耐えない

Parakeet が非対応の言語（日本語等）や言語自動検出が必要な場面では Whisper が必須のため、単純な置き換えはできない。

## 決定

音声認識エンジンをハイブリッド構成にする。エンジン選択は `config.toml` の `[models] asr_engine`（既定 `"parakeet"`）で制御し、`"whisper"` に戻せば旧挙動（常に mlx-whisper）に戻る。

エンジン振り分け（`asr_engine="parakeet"` のとき）:

```
言語指定あり & Parakeet 対応言語(欧州25言語)  → Parakeet
言語指定あり & Parakeet 非対応言語(ja/zh/ko等) → Whisper
言語未指定                                    → Whisper（そのまま結果を使用）
```

言語未指定時に Whisper へ回す理由: Parakeet に言語自動検出は無く、「Parakeet 対応言語かどうか」を安価に判定する手段が無い。mlx_whisper にも言語判定のみを行う公開 API は無く、内部関数 `model.detect_language()` を使うには非公開のモデルロード・mel スペクトログラム計算等の内部処理を独自に再実装する必要があり、結局 Whisper の通常認識とほぼ同じコストがかかる。そのため二度手間を避け、言語未指定時は Whisper で通常認識しその結果をそのまま返す方式に簡略化した（実装時に検証し確定した設計判断）。

Parakeet 経路での実装上の注意:

- `model.transcribe(video_path, chunk_duration=120.0, overlap_duration=15.0)` の `chunk_duration` 指定は必須。省略（既定 `None`）すると長尺動画（2時間の映画等）で OOM する
- 動画ファイルは内部で ffmpeg 経由で読み込めるため、事前の音声抽出・変換は不要
- モデルはプロセス内で1回だけロードしてモジュールレベルにキャッシュする。1ファイル処理ごとに `mx.clear_cache()` を呼ぶ（parakeet-mlx Issue #34 で反復ロード時の Metal メモリ蓄積が報告されているため。メンテナ回答に基づく対策であり、本プロジェクトでの実機検証では長時間の複数ファイル一括処理による蓄積は確認していない）

セグメント時刻の補正（上記2つの実測欠陥への対応）:

1. 各 sentence の末尾の句読点のみのトークンを走査し、直前の実トークン終端との差が `PUNCT_GAP_MAX`（既定1.0秒）を超える場合は、そのトークンをセグメント終端の計算から除外する（テキストとしては残す）
2. 保険として、隣接トークン間のギャップが `TOKEN_GAP_MAX`（既定2.0秒）を超える箇所でセグメントを分割する
3. 表示時間が `MAX_SEGMENT_DURATION`（既定7秒）を超えるセグメントを、息継ぎ位置で再帰的に2分割する。分割点はセグメント中央部（先頭・末尾から `SPLIT_SEARCH_MARGIN`＝25%を除いた範囲）でトークン間ギャップが最大となる位置を選ぶ。連続発話ではギャップがほぼ 0（実測: 24秒のセグメントで111箇所中8箇所のみ非ゼロ、最大0.24秒）のため、探索範囲を中央に限定しないと1トークンだけの断片が量産される
4. 補正後 `end <= start` になるブロックは既存の `_segments_to_srt()` と同方針で破棄する

補正 1・2 だけでは長い連続発話に効かないことが実機検証で判明したため、補正 3 を追加した。実装後の実測（`2001: A Space Odyssey`、3分クリップ、Parakeet 経路）:

| クリップ | | ブロック数 | >7秒 | >10秒 | 最長 | 中央値 |
|---|---|---:|---:|---:|---:|---:|
| 対話区間A | 補正3の前 | 62 | 4 | 0 | 9.00秒 | 1.6秒 |
| 対話区間A | 補正3の後 | 66 | 0 | 0 | 5.76秒 | 1.80秒 |
| 対話区間A | （Whisper） | 53 | 3 | 0 | 8.10秒 | 1.6秒 |
| 対話区間B | 補正3の前 | 48 | 8 | 1 | 24.08秒 | 2.4秒 |
| 対話区間B | 補正3の後 | 59 | 0 | 0 | 6.24秒 | 2.80秒 |
| 対話区間B | （Whisper） | 56 | 0 | 0 | 4.40秒 | 2.7秒 |

ブロック数の増加は穏当（62→66、48→59）で中央値も Whisper と同等であり、過分割は起きていない。台詞ゼロ区間のクリップ2本は補正の前後とも 0 ブロックを維持している。

## 却下案

- **Qwen3-ASR**: 検証対象から除外（本プロジェクトでは実機検証を行っていない）
- **IBM Granite Speech 4.1**: 検証対象から除外（本プロジェクトでは実機検証を行っていない）
- **whisper-large-v3-turbo**: 速度改善は見込めるが、無音区間のハルシネーション傾向は whisper-large-v3 系と共通の課題であり、根本解決にならないため見送り

## 影響

- ファイル構成: `transcribe.py` はエンジン振り分けのディスパッチャに変更。実装は `asr_whisper.py`（mlx-whisper、旧 `transcribe.py` をそのまま移設）と `asr_parakeet.py`（parakeet-mlx、新規）に分離
- 公開契約 `transcribe(video_path, language=None) -> (srt_text, lang)` は変更なし。`whisperai.py` は無変更
- `requirements.txt` に `parakeet-mlx` を追加（`mlx-whisper` は残す）
- 初回実行時、Parakeet モデル（`mlx-community/parakeet-tdt-0.6b-v3`、約2.3GB）の追加ダウンロードが発生し得る
- 日本語・中国語・韓国語などの動画では引き続き Whisper が使われるため、無音区間のハルシネーションの課題はこれらの言語では未解決のまま残る
- `asr_engine = "whisper"` へ戻すことで、Parakeet 導入前の挙動に即座に戻せる
